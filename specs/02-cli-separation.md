# 02 CLI Separation

Node-only scripts (migrations, backups, production start) live in `cli/`, type-checked separately, and never pull in SvelteKit or Vite-only APIs.

## Ideas

- Enforce the boundary structurally (tsconfig project references, scoped lint rules, resolver conditions) rather than by scanning output.
- Node.js runs `.ts` directly (type stripping) — no build step for scripts.
- Make it obvious from the path which `src/` code `cli/` may import (e.g. Node subpath imports like `#cli/*`, which are also easy to lint).

## Checklist

- [x] `cli/` has its own tsconfig: no `DOM` lib, Node types only, no SvelteKit types.
- [x] `vpr check` fails if `cli/` imports (directly or transitively) `$app/*`, `@sveltejs/kit`, or uses `import.meta.env`/`import.meta.glob`.
- [x] Every `cli/` entry runs with plain `node` (verified by hand, see Decisions).
- [x] A deliberately bad import is caught (try it, then revert).

## Decisions

- `#cli/*` maps to `cli/*`, like `src/` uses `#lib/*`. Imports use subpath imports (`#…`), even within the same folder, matching the editor's `non-relative` auto-import (`.vscode/settings.json`). Lint blocks every `./` and `../` import except `./$types.ts`, which SvelteKit resolves through `rootDirs`. Where no subpath applies, an inline disable marks the import (`./env.ts` in `src/env.test.ts`, `./layout.css` in `src/routes/+layout.svelte`): a mapping for one caller isn't worth it, and `#src/*` would give `src/lib` and `src/db` a second spelling. `#routes/*` gets added once routes import their own files (e.g. `queries.server.ts`, [06](./06-query-layer.md)). Rejected: allowing same-folder `./` (`./schema.ts` in a procedure would get past the [06](./06-query-layer.md) import ban, which matches the import text). `cli/` imports `src/` through `#lib/*` and `#db/*`. A dedicated, CLI-safe `src/` folder with its own alias (e.g. `#shared/*`) was rejected: the type check below already guarantees safety, so the extra alias isn't worth it.
- `cli/tsconfig.json` extends the root config and overrides `rootDirs` (empty, so `./$types` doesn't resolve), `lib` (`ESNext`, no DOM; it may type APIs newer than the pinned Node.js, accepted for simplicity), `types` (`node` only, so no `$app/types`), and `paths` (empty, so `kit.alias` entries, which plain `node` can't resolve, aren't inherited). It adds `erasableSyntaxOnly` for type stripping. `vpr check` runs `tsc -p cli` after `svelte-check`.
- How violations fail: `$app/*` doesn't resolve without SvelteKit types. `import.meta.env`/`glob` fail without Vite client types. Both hold transitively, since every imported `src/` file is checked under this config.
- `@sveltejs/kit` is caught because its types declare `$app/*`: any import of it (direct, side-effect, or inside a library's `.d.ts`, e.g. `@sveltejs/adapter-node`) makes the `$app/*` line in `cli/canary.ts` stop erroring (`TS2578`). This relies on kit's type layout. Importing the `vite` package is allowed: it runs under Node, and only its client types (`import.meta.env`/`glob`) are Vite-only. Rejected: `paths` mapping kit/vite to a non-module stub (misses side-effect imports and library `.d.ts` files), and grepping `tsc --explainFiles` or `--listFilesOnly` for package imports (only adds coverage for `vite` itself, and shell pipes aren't portable to Windows).
- `cli/canary.ts` is a permanent negative test (`@ts-expect-error` on `$app/env`, `import.meta.env`, DOM, enum), so a weakened config fails `vpr check`. One probe each is enough: `$app/env/private`/`public` are declared by the generated `$app/types`, which imports kit and so also declares `$app/env`, and `vite/client` declares `import.meta.env` and `glob` together. It also catches `/// <reference types="vite/client" />`, which makes the `import.meta.env` line stop erroring (`TS2578`).
- `src/` → `cli/`: ESLint bans `#cli/*` under `src/`, so CLI-only queries and procedures stay private ([06](./06-query-layer.md)). With relative imports banned too, only dynamic imports get past it (accepted). It's not a checklist item. An earlier regex (`#cli/*` or `../cli/`) was removed, since it missed relative paths the import ban now covers. TypeScript can't block relative imports, and `rootDir` doesn't fit, since the root project spans `src/` and root configs. `cli/` importing `src/` via `#lib/*` rather than `../src/` is a convention for `AGENTS.md` ([13](./13-agent-docs.md)): both resolve to the same file, and the type check covers it either way.
- Rejected: project references (they need `composite`, and tsserver would still check `src/` files under the root project), and scanning built output.
- Verified by hand, then reverted: a sample entry importing `#cli/*` and `#lib/*` ran with `node` and passed `vpr check`. Adding `$app/env` to the entry, or re-exporting `#db/app/client.ts` (which imports `$app/env/private`), failed `vpr check`.
- Layout: grouped by feature (`cli/db/`, later e.g. `cli/db/backup.ts`), shared modules flat at the top. CLI-only queries and procedures go in `cli/db/[database]/[prefix]/`, mirroring `src/db/` ([06](./06-query-layer.md)). No `lib/` or entries split until there are several.
- Env: scripts don't read env files in TS. Each `package.json` script loads only the files its variables can come from, with Node's `--env-file` / `--env-file-if-exists` (later files win, the process env wins over all, like Vite; `NODE_OPTIONS` rejects `--env-file`, so the flags go on each command). The script parses each value it uses on its own (e.g. `v.parse(DbEnvSchema.entries.DATA_DIR, process.env.DATA_DIR)`, see [03](./03-environment.md)), and takes the mode as `--mode=[mode]` (`node:util` `parseArgs`). Exception: drizzle-kit configs, see [05](./05-database.md). Skipping a `*.local` file means ignoring its overrides, so include them wherever a script's variables could be overridden.
- The CLI database client is `openDbs({ dataDir, mode, scriptPath })` (`cli/db/client.ts`). It uses [05](./05-database.md)'s shared connection factory and is audited like SvelteKit's ([07](./07-audit-logging.md)). It returns `db`, `auditedDb`, and `auditDb` (`undefined` in development) for scripts that work on audit entries, like the purge. It's disposable (`using`), closing both connections.
