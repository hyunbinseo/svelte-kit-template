# 06 Query Layer

How routes, remote functions, and CLI scripts reach the database. This is the most open spec.

## Ideas

- Plain functions taking `db`, bound query sets, repository modules, or per-route `server.ts` — pick what reads best at the call site and in tests.
- Audited reads as a per-call or per-module choice.
- Enforce "sync transaction callbacks" with types.
- Domain verbs for names (`find`, `create`, `claim`, `mark`, `link`, `discard`, `grant`, `revoke`) over SQL verbs.

## Checklist

- [x] Transactions reject async callbacks (type error). `node:sqlite` is sync; an async callback would commit early.
- [x] Read-then-write paths run in `immediate` transactions.
- [x] Multi-row invariants (e.g. closing a user revokes their roles and sessions; granting a role requires an active user without it) live in procedures shared by SvelteKit and CLI.
- [x] Deletes that span tables are procedures too, e.g. one that deletes logins with their attempts (children first), called by closing a user ([08](./08-auth.md)) and the purge job ([12](./12-operations.md)).
- [x] Each procedure runs in one transaction, reads the clock inside it, guards every row it depends on, returns falsy on no-op — and each guard is tested.
- [ ] Reads are not audited by default; a route can opt in ([07](./07-audit-logging.md)).
- [x] Drizzle's sync API is used.
- [x] Values are always bound, never written into SQL text, so errors and telemetry carry no data ([10](./10-observability.md)). `sql.raw` is for identifiers and constants only; ESLint flags it for review.
- [x] Every read of a soft-deleted table states its filter inline (e.g. `isNull(t.revokedAt)`), including expiry where the table has one (e.g. `gt(t.expiresAt, now)` for sessions), and procedure tests cover it. Drizzle has no global scopes, so a hidden default couldn't be enforced (like Rails' `discard`, not Laravel's `SoftDeletes`).

## Decisions

- Procedures are plain functions in `src/db/app/server/procedures/` (one file per table name prefix, like `schema/`), taking the database as their first argument: `closeUser(db, { closedBy, closedReason, id })`. Routes, remote functions, and CLI scripts call the same function with their own client, and tests pass `createTestDatabase()` ([11](./11-testing.md)). They never import `$app/*`, so `cli/` can import them (checked by `tsc -p cli`). Domain verbs name them (`closeUser`, `grantRole`, `revokeRole`, `deleteLogins`). Rejected: bound query sets and repository modules (a client bound at import pulls in `client.ts`, which `cli/` and tests can't import); per-route `server.ts` (CLI can't share it).
- `src/db/app/server/database.ts` holds what every client shares: the `AppDb` and `AppTx` types and `createDatabase(client)`. The SvelteKit client, `createTestDatabase`, and later the CLI client all call it, so tests run the same `transaction` as the app. Test databases migrate through a plain Drizzle instance on the same connection, since `migrate()` needs Drizzle's own class type.
- `db.transaction(callback, { behavior: 'immediate' })`: `AppDb` replaces Drizzle's signature, so the config is required, only `immediate` type-checks, and an async callback is a type error (`T extends PromiseLike ? never`, like Drizzle's own for sync drivers). `createDatabase` only casts Drizzle's client to `AppDb`; nothing is checked at runtime. Immediate, since every procedure reads before it writes, and a deferred transaction lets another writer slip in between (or fails with `SQLITE_BUSY` on upgrade, which the busy timeout doesn't retry). Left to review, since the type can't see them: a callback typed `any` or `unknown` that returns a promise (it would commit at its first `await`, and later statements would run outside the transaction), and casts. Rejected: runtime assertions in a wrapper (an `isPromise` check and a behavior check, for cases typed code rarely reaches); a `transaction(db, callback)` helper with ESLint flagging direct `.transaction()` calls; defaulting to `immediate` silently (the call site wouldn't show it).
- Parameters: one per table the caller writes, named after the table and typed as a `Pick` of its `Select` type, e.g. `closeUser(db, user)` with `user: SetNonNullable<Pick<UserSelect, 'closedBy' | 'closedReason' | 'id'>, 'closedReason'>`, read as `user.id` and `user.closedBy`. `Select`, because every column is a required key there: `Insert` would let a nullable column like `closedBy` be left out (`undefined`), which Drizzle skips instead of writing `null` (the system). Columns that must not be `null` here use type-fest (`SetNonNullable`); narrower values use `SetFieldType` with a partial enum list (e.g. `revokeRole` takes `UserRoleRevokeReason`, without `cascade_` reasons, [05](./05-database.md)). Values the procedure derives (the clock, a cascade's actor and reason, foreign keys) aren't parameters, so `closeUser` touches six tables but takes one `user`. Several tables mean several parameters (`(db, user, userProfile)`), so same-named columns can't collide. A value shared across tables (a parent's ID and the child's foreign key) is passed once, on the parent, and the child's `Pick` leaves the foreign key out (`user: Pick<UserSelect, 'id'>`, `userProfile: Pick<UserProfileSelect, 'birthDate'>`), so the two can't disagree. Rejected: destructured column names (`{ closedBy, closedReason, userId }`, a second type listing for each field, and `userId` isn't a `user` column); `Insert`-based types (see above; type-fest's `SetRequired` keeps the explicit `undefined`).
- Two kinds of procedures. Entry points take `db: AppDb`, open one transaction, and read the clock inside it (`new Date()`, so tests use fake timers). Shared steps take `tx: AppTx`, so the type requires a caller's transaction, e.g. `deleteLogins(tx, where)`, called by `closeUser` and later the purge job ([12](./12-operations.md)). It deletes `login_attempt` rows first, then `login`, each its own statement ([05](./05-database.md)). `AppTx` omits `transaction`, so savepoints don't type-check. Rejected: one signature for both, nesting via savepoints (the inner one would read its own clock, and a no-op couldn't tell the caller to stop).
- Guards: an entry point checks every row it depends on inside its transaction (target user active, actor active unless `null`, role active or not) and returns falsy without writing when one fails: `false`, or `undefined` where it returns an ID. Updates also repeat `isNull(…At)` in their `WHERE`, so a final group is never overwritten ([05](./05-database.md)). Authorization (is the actor an admin?) stays in routes ([08](./08-auth.md)): procedures also serve the CLI, where the actor (`closedBy`, `assignedBy`, …) is `null`. Each guard has a test that checks the return value and that nothing changed.
- `closeUser` implements [08](./08-auth.md)'s closing: it revokes active roles and unexpired sessions with `cascade_user_closed` and the triggering actor, deletes the profile and the logins matched by user ID or contact, and erases the contact unless banned. Expired sessions stay as they are: they're already invalid, and the purge job deletes them.
- Soft-delete filters are written inline in each query (`isNull(t.revokedAt)`, plus `gt(t.expiresAt, now)` for sessions). `where` filters put one condition per line, so the soft-delete filter stands out; a trailing `//` after the first keeps the formatter from joining short ones. Procedure tests seed revoked and expired rows next to active ones and check that they're left alone.
- Sync API only: queries end in `.run()`, `.all()`, or `.get()`. ESLint flags `await` under `src/db/` (Drizzle's builders are thenable, so `await` would also work, but async code can't run inside a transaction). Insert `.get()` is fine since 1.0.0-rc.5: it types as `T | undefined` when the insert may return no row, e.g. with `onConflictDoNothing()` ([drizzle-team/drizzle-orm#6107](https://github.com/drizzle-team/drizzle-orm/issues/6107)).
- Audited reads: not built yet, since there's no audit logger until [07](./07-audit-logging.md). Planned shape: procedures already take their client as an argument, so a route opts in per call by passing an audited client instead of `db`. The box stays open until then.
